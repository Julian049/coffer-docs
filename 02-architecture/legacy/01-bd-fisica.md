# Diagrama físico de la base de datos

## Estado del MVP (v0.1.0)

### PostgreSQL (servidor), después de `V1__first_schema.sql` + `V2__fix_schema.sql`

```mermaid
erDiagram
    transactions {
        BIGINT server_id PK "GENERATED BY DEFAULT AS IDENTITY, NOT NULL"
        UUID local_id UK "uq_transactions_local_id, NOT NULL"
        VARCHAR_100 title "NOT NULL"
        NUMERIC_19_4 value "NOT NULL, signo = ingreso/gasto"
        BOOLEAN type "NOT NULL, redundante con el signo"
        TEXT description "NULL"
        TIMESTAMPTZ date "NOT NULL DEFAULT now()"
        BOOLEAN synchronized "NOT NULL, estado del cliente"
    }
```

### Room / SQLite (dispositivo Android), `AppDatabase` version 1

```mermaid
erDiagram
    transactions {
        TEXT localId PK "UUID generado en el cliente"
        TEXT title "NOT NULL"
        REAL value "Double"
        INTEGER type "Boolean"
        TEXT description "NULL"
        TEXT date "String ISO-8601 (o texto crudo si falla formatDate)"
        INTEGER synced "Boolean, default 0"
    }
```

Observaciones:
- No hay tabla de usuarios: todos los datos son globales.
- `value` se guarda como `NUMERIC` en la BD, pero se mapea a `double` en Java y Kotlin.
- No hay `updated_at` ni `deleted_at`, así que no se pueden sincronizar ediciones ni borrados.
